# Feature scaffolds

Each file here describes one feature family from the original dashboard this starter is
distilled from: what it is, the design choices that mattered (and why), the mistakes
already made for you, and a build sketch your Claude agent can work from. They are
deliberately code-free — your version should grow out of your own semester, not a port.

Use them lazily. When a phase of `../../ROADMAP.md` or a complaint of your own points at
one of these, have your agent read that one file before designing anything. Reading them
all up front is a waste of a good evening.

| File | Build it when... |
|---|---|
| `todays-focus.md` | you stop trusting your own sense of what's most urgent |
| `readings-pipeline.md` | the pile of postings outgrows your downloads folder |
| `primers.md` | you keep walking into class not knowing why the readings mattered |
| `study-loop.md` | you realize you remember nothing from week 2 |
| `exam-prep.md` | the first midterm is three weeks out |
| `grade-weighted-priorities.md` | two courses collide and you must choose what slips |
| `day-plan.md` | school starts eating the rest of your life |
| `automation.md` | you're doing anything manually twice a day |

One meta-lesson that applies to every file here: the original versions of all of these
were built *after* their owner felt the pain they solve, usually the same day. Features
built ahead of need got deleted; features built from complaints survived. Let your
backlog be your annoyances.
